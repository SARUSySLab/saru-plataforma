## 3. Princípios já ratificados que restringem o preço

1. **P3 = foco do MVP** (decisão 2026-07-15), a matriz nasce do relatório track day e cresce p/ os demais.
2. Sequência de receita: consultoria → SaaS; preço internacional em USD/EUR, custo em BRL.
3. Pitch só afirma o que o código sustenta → não cobrar por 14-DOF enquanto roadmap.
4. CAC B2B manual (mídia paga só pós-1º contrato) → ticket B2B precisa sustentar venda 1:1.
5. Gamificação P2 fecha loop com recompensas reais → custo de rewards entra na margem do tier P2.
6. Anti-slop: tabela pública simples; "fale conosco" só em contrato B2B/organizador.

### 4.2 Modelo + packaging, metodologia (skill `pricing-strategist`, 2026-07-16)

> Rodada determinística da skill (model-picker + packaging-designer) sobre os dados 10/10 do §2.
> Disciplina da skill: recomenda **modelo + faixa**, nunca o número, o número é o martelo do Vinicius.
> **E1 FECHADO** = modelo por segmento + packaging com gatilho de upgrade + gate de validação (Van Westendorp).

**Modelo de preço por segmento (model-picker, fit-score 0-100):**

| Segmento | Modelo recomendado | Fit | Racional (determinístico) |
|---|---|---|---|
| **P3 track day** 🎯 | **Freemium → usage** (per-evento) + assinatura anual | freemium **85** · usage 75 | Curva bottom-up (PLG) + base ampla + variância de uso alta (por evento) |
| **P1 equipe (SARU Pro)** | **Hybrid** (assinatura por assento **+** créditos de simulação) | hybrid **95** · seat 85 | Sinais seat E usage presentes; espelha o modelo do ARD (£/mês + créditos); mercado já treinado em subscription |
| P2 sim racer | Freemium + assinatura (segue P3 digital) |, | Volume, PLG; paridade Track Titan/Trophi |
| Organizador (B2B2C) · Consultoria | Usage (fixo + por-carro · por-evento/day-rate) |, | Marginal variável; não é SaaS de assento |

**Packaging B2C digital, Good/Better/Best (packaging-designer + decisão humana):**

O detector de anti-padrões apontou o erro clássico: com a lógica pura "alta importância → grátis", o
**relatório interpretado caía no Free → nenhum gatilho de upgrade** (Ramanujam, erro #4). Decisão de
packaging (o que a skill defere ao humano): **gatear o valor interpretado atrás do Plus.**

| Tier | Preço-frame | Conteúdo | Papel |
|---|---|---|---|
| **Free** | R$ 0 | Upload + parse · comparar as próprias voltas (delta/speed/brake) · canais básicos · dado não-persistido (TTL) | Isca PLG: sente valor, não resolve sozinho |
| **Plus** | ~R$ 49/mês | **+ Referência simulada (overlay) + Relatório Track Day interpretado (E2) + todos os canais + histórico durável** | **Gatilho de upgrade**, é o que o P3/P2 paga (o "onde perco tempo e o que treinar") |
| **Pro** | ~R$ 99/mês | + KPIs de coaching avançados + plano de treino + relatórios/sims ilimitados + prioridade de sim + multi-veículo | Power user / P1 entrada; Best precisa ser salto real de valor (evitar decoy 2×preço/0,8×valor) |

**Gate de validação (obrigatório antes de publicar tabela), Van Westendorp PSM:** ainda **sem dado
de WTP** (a skill exige N≥30/segmento; hoje N=0). Rodar as 4 perguntas (barato demais / barato /
começando a ficar caro / caro demais) nas **~10 primeiras conversas reais**, P3 em evento BSB +
P1 nas parcerias, e passar por `wtp_analyzer.py` p/ obter a Faixa de Preços Aceitáveis (RAP) e o
Optimal Price Point antes de fixar. Os números do §4.1 são **âncoras candidatas dentro dessa faixa**,
não a tabela final. Lançamento com desconto de parceiro-fundador documentado (não queima âncora).
